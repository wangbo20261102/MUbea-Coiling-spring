# MUbea-Coiling-spring

UR5 单次矩形运行程序：`ur5_rectangle_once.script`。

## 路径与单位

原始文件位于 `坐标/`，单位 cm；脚本换算为 m，使用底座坐标系。
按四份文件的 X/Y 最小值与最大值组成矩形，不将它们当作机器人关节硬限位。

| 顺序 | X（mm） | Y（mm） | 运行 Z（mm） |
|---|---:|---:|---:|
| 坐标1对应角 | 175.9 | -664.4 | 110 |
| 坐标2对应角 | -448.2 | -664.4 | 110 |
| 坐标3对应角 | -448.2 | 209.3 | 110 |
| 坐标4对应角 | 175.9 | 209.3 | 110 |

Z 下限为底座坐标系中的 **100 mm**。原始四点的 Z 均低于此值，因此不沿用原始 Z。
默认 `z_run=0.110`，为下限留出 10 mm 余量；可调整，但不可小于 `z_floor=0.100`。
全部保持启动时的 TCP 姿态，结束时返回启动时的完整 TCP 位姿；不要求返回相同关节构型。

路径：记录启动位姿 → 原地升到过渡高度 → 平移至角1上方 → 到角1 → 角2 → 角3 → 角4 → 原地升到过渡高度 → 平移到启动点上方 → 回到启动位姿。
过渡高度取启动 Z 与运行 Z 的较大值。高位启动时先水平转移再下降，避免在启动点先下降。
只运行一次；角4之后直接按上述路径返回启动点，不额外走角4→角1。

## 在示教器中使用

1. UR5 CB3 控制器软件要求 **PolyScope 3.14.3 或更新的兼容 3.x 版本**。旧版本没有所需的 `get_inverse_kin_has_solution`。本文件不是 `.urp` 程序文件。
2. 在 Installation 中确认当前 TCP、负载、安装方向和机器人安全限制与实机一致。坐标文件没有工具姿态，脚本使用启动时的实际工具姿态。
3. 将脚本复制到示教器可访问的位置。新建机器人程序，添加 **Script → File** 节点并选择该文件。文件包含定义和调用，不需要另外添加函数调用。
4. 关闭机器人主程序的 **Program Loops Forever / 程序无限循环**，也不要把 Script 节点放进循环节点中。脚本内部的一次运行不阻止外层程序重复调用。
5. 在启动 TCP 的 Z≥100 mm 时启动。默认速度 20 mm/s、加速度 50 mm/s²、圆滑半径 0；先在匹配版本的 URSim 验证，再在实机低速检查完整路径。

## 检查范围与限制

首次运动前，程序对所有运动段（包括回程）以不超过 5 mm 的间隔检查 Z、逆解、配置的安全限制及相邻逆解的关节变化。无逆解或单关节跳变超过 0.35 rad 时停止。
这些检查可能因启动姿态拒绝执行，即使四个原始点曾经分别可达；组合后的矩形角及连接线也需要独立验证。
每段运动前和返回后检查实际 TCP Z。出错后终止，不执行自动回原点的补救动作。

这里的 Z 限制约束的是 **TCP**，并非整条机械臂或工具外形。离散逆解检查不证明整段无奇异点、无碰撞，也不是实时的安全高度保证。
若 100 mm 是必须由实机保证的边界，应结合实际工具几何及制动距离，在机器人 Installation 中配置相应的安全平面/限制；软件余量和段间检查不能替代这些限制。

程序未连接机器人，未经过 URSim 或实机验证。仓库附有离线逻辑测试（模拟 UR 接口），可用 `python -m unittest discover -s tests -v` 运行；它不验证控制器语法、真实逆解或碰撞。
